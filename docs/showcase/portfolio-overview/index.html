Developer Portfolio Overview

9 min read

In roughly two years of active development, this developer built 38 Swift packages spanning games, compilers, biofeedback, AI tooling, and financial mathematics — connected by shared infrastructure, a zero-tolerance quality gate, and a design-first practice that treats the written proposal as the first deliverable.

Overview

Between November 2024 and November 2026, this developer shipped 38 Swift projects, 306 releases, and 5,410 commits across iOS, macOS, tvOS, visionOS, and watchOS. The work does not read as a collection of experiments. It reads as the construction of an ecosystem: a quality gate that enforces its own rules, an identity and OAuth layer that multiple packages depend on, an MCP infrastructure that spans both client and server, a game whose rules engine, match orchestrator, AI layer, UI, CLI, server, and web client are each their own package, and a financial mathematics library with its own Excel function registry and file format support.

Three themes recur across the whole body of work. First, shared infrastructure over repetition: when a concept appears in more than one project — logging, TLS, concurrency primitives, corpus access, terminal UI — it becomes its own package rather than being reimplemented. Second, fidelity as a design constraint: whether the subject is Applesoft BASIC (1979 behaviour wins), Potrace (derived from the paper, not the C source), OAuth (rotation failures are the reason this is a library), or iConquer (a reference TypeScript port drives behavioral parity), the explicit goal is correctness against a specification rather than approximate functionality. Third, process encoded in tooling: development guidelines are versioned and vendored, quality gates run on every commit, and AI-assisted sessions operate within a documented rulebook.

The trajectory is visible in the data. The earliest projects — ApplesoftBASICLib, ApplesoftBASICAppCore, QualityGateCore — establish the foundation: an interpreter, a quality gate, and the guidelines that govern everything else. Later projects grow increasingly interconnected, consuming and extending the shared layer. By late 2026, projects like SwiftCLIKitAuth are referencing approved design proposals by revision number before a line of code is written.

Technical Breadth

The portfolio is exclusively Swift, which turns out to be a breadth statement rather than a constraint. The language is applied to domains that routinely use different stacks entirely:

  • Compiler/interpreter engineering: ApplesoftBASICLib implements a complete Applesoft BASIC interpreter with lo-res and hi-res graphics, a line editor, and period-accurate error messages. CTokenizer implements a Mixture-of-Experts inference engine streaming 200GB+ models through a custom Metal compute pipeline with seven GPU optimization paths.
  • Game engine architecture: The iConquer ecosystem spans eight packages — rules engine, match orchestrator, AI agents, CLI client, SwiftUI presentation layer, WebSocket server, MCP integration, and a shared game view model — each with its own release cadence.
  • Protocol implementation: SwiftWebAuthn implements the W3C WebAuthn specification’s two ceremonies from the specification text. SwiftOAuthCore implements both halves of OAuth 2.0 with storage as a protocol. MCPClient implements the Model Context Protocol client specification.
  • Financial computation: BusinessMath, SwiftExcelFunctions, SwiftXLSX, SwiftZIP, and SwiftExcelCore form a stack that reads Excel files, parses formulas with a Pratt-precedence parser, evaluates them against Excel’s exact semantics, and can export results back.
  • Biofeedback signal processing: narbis implements a patented HRV coherence algorithm entirely on-device using BusinessMath’s FFT and streaming statistical infrastructure, targeting iOS, watchOS, visionOS, and Android via Swift 6.3 SDK.
  • Static analysis: QualityGateCore performs AST-based Swift analysis via SwiftSyntax, with cross-file symbol resolution through the compiler’s index store, dated suppression, and per-checker precision calibration.
  • Server-side Swift: IconquerServer is a SwiftNIO WebSocket server with actor-isolated concurrency throughout. WebScraper is a Vapor application with Postgres, Redis queues, Stripe payments, and Leaf templates. SwiftMCPServer is an HTTP MCP server implementation.

Platform coverage includes every current Apple platform. The shared dependency list — 53 named packages — reflects genuine breadth: mlx-swift for on-device ML, swift-syntax for AST analysis, fluent-postgres-driver for server persistence, swift-nio-ssh for terminal SSH, stripe-kit for payments, swift-certificates and swift-asn1 for TLS and WebAuthn.

Craft Signals

Design-first workflow, documented and enforced. The development-guidelines repository describes a Design-First TDD process as a named practice. CTokenizer is formally tagged as using this workflow. SwiftCLIKitAuth references its approved design proposal by revision number (rev 7, with revs 8 and 9 recorded as decided by the user) before the MASTER_PLAN is written. The iConquer ecosystem maintains a TypeScript reference port explicitly as a behavioral specification, enabling parity testing. Across the portfolio, projects arrive with stated missions, named target users, and explicit differentiators — not as retrospective documentation but as the document that precedes implementation.

Quality gate as first-class infrastructure. QualityGateCore has 779 commits and 15 releases, making it the most heavily developed single package in the portfolio. It enforces its own rules on itself. It ships a reusable GitHub Actions workflow. Its DocC documentation checks — doc-code, doc-run, doc-claims — verify that published figures match what the code actually computes, not what the author believed when writing. The org-judgement-corpus captures 111 projects’ worth of telemetry, 138 daily pulse reports, and 11 weekly narratives, creating a longitudinal quality record rather than a point-in-time snapshot.

Zero-tolerance warning policy, applied portfolio-wide. IconquerServer, MCPClient, SwiftMCPServer, and SwiftExcelFunctions all explicitly state Swift 6 strict concurrency with a zero-warning quality gate. SwiftZIP, SwiftOAuthCore, and SwiftWebAuthn describe their types as Sendable throughout. This is not incidental — 27 of 38 projects carry a CLAUDE.md that encodes the rules for AI-assisted sessions, making the policy machine-readable.

Dependency discipline as a stated value. Multiple project descriptions treat their dependency count as a design decision rather than an implementation detail. SwiftZIP names “zero external dependencies” as its first differentiator. SwiftSVG is “Foundation only — that single constraint is the product.” QualityGateTypes is explicitly a leaf dependency with no third-party runtime dependencies. When MCPClient grew dependencies beyond its original claim, the MASTER_PLAN was updated to record the honest current state rather than preserving the aspirational one — a sign that project documentation is treated as a living artifact, not a marketing document.

AI-assisted development with institutional memory. 259 of 5,410 commits are AI-assisted across 19 Claude Code sessions. The IJSCore project exists specifically to capture quality gate telemetry, refine it into “Institutional Pulse” documents, and feed lessons back into future sessions — a closed loop designed to prevent what its mission statement calls “contextual naivety” and “confident wrongness.” The development-guidelines repository is described as a “versioned, vendorable rulebook” that AI assistants read at session start. This treats AI assistance as a practice to be governed, not a feature to be adopted ad hoc.

Release discipline. 306 releases across 38 projects, with SwiftXLSX at 47, SwiftMCPServer at 39, SwiftOAuthCore at 29, CorpusKit at 34, and SwiftCLIKit at 23. The distribution suggests packages with external consumers are versioned frequently and deliberately — semver as a commitment, not a formality.

Key Projects

QualityGateCore is a static analysis tool for Swift 6 projects that runs AST-based checkers for correctness, safety, concurrency, security, and documentation using SwiftSyntax and the compiler’s index store. It exists because the gap between “the code compiles” and “the code is correct” is where bugs live, and closing that gap with a local gate on every commit is faster than finding defects in CI or review. At 779 commits and 15 releases, it is the portfolio’s most sustained investment and the infrastructure that governs every other project. Its documentation checkers — which verify that code examples in documentation actually compile and that published figures match computed ones — are the clearest signal that quality is defined precisely enough to be automated.

SwiftExcelFunctions is Excel’s function library in Swift: a registry a caller can query by the name Excel uses, backed by BusinessMath‘s mathematics so there is only one implementation of any given computation. It exists because evaluating spreadsheet formulas correctly requires Excel’s exact argument order, coercion rules, and error propagation — not similar ones — and because a second NPV implementation that could disagree with the first is more dangerous than no implementation. At 270 commits and 21 releases, with 116 AI-assisted commits across 3 Claude Code sessions, it represents the most intensive AI-collaborative development in the portfolio, applied to a domain where semantic correctness is the entire product.

ApplesoftBASICLib is a faithful Applesoft BASIC interpreter in modern Swift, intended to run programs written in 1979 the way they behaved in 1979 — including the surprising parts. It exists as a library first, embeddable rather than locked inside a terminal application, and includes Apple II lo-res and hi-res graphics. The companion ApplesoftBASICAppCore brings it to iPad, Mac, and Vision Pro with period-accurate fonts and a green-on-black terminal. This project is notable not for its scale but for the clarity of its design constraint: “Where 1979 behaviour and modern taste disagree, 1979 wins — including the error messages.”

MCPClient is a spec-compliant Swift MCP client enabling any Swift application to connect to MCP servers, discover tools and resources, and invoke them over HTTP/SSE, stdio, or WebSocket transports. It exists because MCP is the emerging standard for AI tool use and no production-quality Swift implementation existed. At 110 commits and 9 releases, it is the client half of a two-package MCP infrastructure — SwiftMCPServer is the server half — that now underpins IconquerMCP, BusinessMathMCP, GeoSEOMCP, SearchOperatorCore, and WebScraper. The MASTER_PLAN’s honest correction of its original “zero dependencies” claim — acknowledging that each dependency was taken on deliberately for a named feature — is representative of how project documentation is maintained across the portfolio.

CTokenizer is a Swift inference engine for Mixture-of-Experts language models on Apple Silicon, streaming 200GB+ models from NVMe through a custom Metal compute pipeline using approximately 6GB resident memory. It exists to run large models locally that cannot fit in unified memory, and it does so with a runtime-configurable architecture so no model dimensions are hardcoded. The 255 tests run against tiny synthetic model fixtures, meaning no 200GB download is required to verify correctness. This is the only project formally tagged with the design-first workflow, suggesting the Metal pipeline and memory architecture were specified before implementation began.

The iConquer ecosystem — IconquerCore, IconquerMatch, IconquerAI, IconquerUI, IconquerCLILib, IconquerServer, IconquerMCP, IconquerClient, and IconquerGameKit — is a modern Swift port of a Risk-style strategy game originally written in 2002. It exists as a portfolio-quality demonstration of layered architecture: the rules engine has no UI dependency, the match orchestrator is agent-agnostic, the AI layer is deterministic under fixed seeds, the server is actor-isolated throughout, and the presentation layer is a library serving every platform shell rather than being reimplemented per target. A reference TypeScript implementation drives behavioral parity testing. Across nine packages, the ecosystem spans 393 commits and 32 releases.

SwiftOAuthCore implements both halves of OAuth 2.0 — authorization server and client — in one package with storage as a protocol. It exists because presenting a refresh token expires it, and the three failure modes that follow from that each lock a user out of their own data rather than producing a readable error. The MASTER_PLAN names these failures explicitly as the reason this is a library rather than a snippet. At 145 commits and 29 releases, it is one of the most released packages in the portfolio, reflecting its role as shared authentication infrastructure for SwiftMCPServer, MCPClient, and other consumers.

development-guidelines is a versioned, vendorable rulebook for AI-assisted Swift development: Design-First TDD, a zero-tolerance warning quality gate, and setup scaffolding for new projects. It exists because rules that cannot be checked are not enforced, and because an AI assistant that reads the rules at session start operates within a documented constraint rather than a convention that must be re-established every time. At 167 commits and 17 releases, with rules that failed in practice recorded alongside the failure, it is the metacognitive layer of the entire portfolio — the document that explains why the other 37 projects are built the way they are.
