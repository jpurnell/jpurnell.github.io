# Two Years at the Edge of the Swift Ecosystem

> In roughly two years and 2,670 commits across 28 Swift packages, this developer built a coherent, interconnected platform spanning AI agents, multiplayer game infrastructure, biofeedback, terminal UIs, MCP tooling, financial computation, and retro computing — always in Swift, always for Apple's full device surface, and always with the quality gate running.

## Overview

The portfolio opens in November 2024 and is still active as of October 2026 — a continuous, accelerating build rather than a collection of completed things. What looks at first like a diverse set of projects resolves, on closer inspection, into three overlapping systems being constructed in parallel: a **game platform** (the Iconquer ecosystem), a **developer-tooling layer** (development-guidelines, CorpusKit, IJSCore, ProjectShowcase, SwiftMCPServer, MCPClient), and a set of **domain libraries** (ApplesoftBASICLib, narbis, SwiftExcelFunctions, SwiftCLIKit, CTokenizer, SwiftOAuthCore) that each solve a hard, specific problem. The three systems share dependencies, share conventions, and share a quality philosophy — which means they are not really separate systems at all.

The trajectory runs from library to ecosystem. Early projects establish foundations: a rules engine, a TLS wrapper, a CLI framework, a math library. Later projects are consumers of those foundations, which means the whole portfolio compounds. By the time IconquerServer, IconquerGameKit, and IconquerUI arrive, they are thin coordination layers on top of six or seven already-proven packages. The same pattern holds in the MCP space: SwiftMCPServer and MCPClient enable BusinessMathMCP, SearchOperatorCore, and IconquerMCP without those projects needing to reinvent transport or authentication.

The `development-guidelines` project — 167 commits, 17 releases — is the connective tissue. It is a versioned rulebook that travels into each project as a vendored artifact, and 21 of 28 repositories carry a `CLAUDE.md` that implements it. The rules are not aspirational: they include an automated quality gate with zero tolerance for warnings, and they carry records of rules that failed in practice alongside the reasons for failure.

## Technical Breadth

Every project is Swift. That is the one constant, and it is a genuine constraint rather than a limitation — the portfolio covers every platform Apple ships (iOS, macOS, tvOS, watchOS, visionOS) and extends Swift into domains where it is not yet common.

**Networking and protocol:** SwiftNIO underlies IconquerServer, IconquerClient, SwiftMCPServer, MCPClient, and SwiftOAuthCore. SwiftNIO SSH is the transport layer inside SwiftCLIKit's embedded SSH server. TLS, certificates, and ASN.1 are handled through the swift-crypto/swift-certificates/swift-asn1 chain. WebSocket transports appear in both MCPClient and IconquerClient. The developer has implemented OAuth 2.0 from both sides — authorization server and client — in SwiftOAuthCore, including refresh-token rotation, PKCE, and protocol-abstracted storage.

**Concurrency:** Swift 6 strict concurrency mode is the standard across the portfolio. Actor isolation, `Sendable` conformance, and structured concurrency appear in project after project — not as aspirational goals but as enforced quality-gate requirements. IconquerServer describes its concurrency model explicitly: every stateful component is a Swift actor; non-Sendable NIO channels are bridged through captured `@Sendable` closures.

**AI and ML:** The Iconquer game platform includes an AI layer (IconquerAI) backed by MLX on Apple Silicon, with self-play training, Wilson-interval win-rate estimation, and pre-registered benchmark criteria. CTokenizer is a Metal compute pipeline for streaming 200GB+ Mixture-of-Experts models through ~6GB resident memory with seven GPU optimization paths. The MCP layer (SwiftMCPServer, MCPClient, IconquerMCP, BusinessMathMCP, SearchOperatorCore) represents a coherent bet on the Model Context Protocol as the integration surface between AI agents and running software.

**Domain mathematics:** BusinessMath underlies SwiftExcelFunctions, narbis, and BusinessMathMCP. SwiftExcelFunctions implements Excel's function library with Excel's semantics — argument order, coercion rules, error propagation — delegating the mathematics entirely to BusinessMath to prevent two implementations from disagreeing. The narbis biofeedback library applies a patented HRV coherence algorithm on-device, targeting pure Swift for cross-platform reach including Android via Swift 6.3 SDK.

**Retro computing and graphics:** ApplesoftBASICLib implements a faithful Applesoft BASIC interpreter where fidelity to 1979 behavior is explicitly the requirement, including Apple II lo-res and hi-res graphics rendering and the period-accurate line editor.

**Vector graphics and static sites:** BoundedIO is a Swift-native implementation of the Potrace bitmap-to-vector algorithm derived from the original paper rather than the GPL C source, enabling an MIT license. SwiftSVG generates SVG markup with Foundation only, no UI framework. PersonalSiteLib is the developer's own site, built with the Ignite static site generator and published from `docs/` with no external build service.

## Craft Signals

**The quality gate is non-negotiable.** Across 21 of 28 projects, `CLAUDE.md` installs a zero-warning quality gate. The `development-guidelines` project documents this gate formally, versions it, and vendors it — so an update is a replacement, not a merge conflict. This is not a style preference; it is an enforcement mechanism. The gate's failures are recorded alongside its rules.

**Design-first is present but sparse.** Only one project — CTokenizer — is formally flagged as using a design-first workflow. However, the `development-guidelines` project describes Design-First TDD as the prescribed process, and multiple projects (IconquerCore, IconquerMatch, IconquerAI, IconquerMCP, MCPClient) carry full CLAUDE.md architecture sections with explicit session-start, development-workflow, and key-rules headings, which is the structural trace of that process even where it is not labeled. The honest read is that the discipline is practiced unevenly and the developer knows it — the guidelines project records failures in practice, not just intentions.

**Libraries before applications.** The pattern is consistent: every user-facing application in the portfolio is thin. IconquerUI holds no game rules. IconquerGameKit is one integration point over three packages. PersonalSiteLib delegates to Ignite. The applications are assembly points; the substance is in the libraries underneath. This makes each library independently testable and independently reusable, which the portfolio demonstrates — IconquerCore is consumed by at least five other packages.

**Semantic versioning and release discipline.** 217 releases across 28 projects. SwiftMCPServer alone has 38 releases; CorpusKit has 34; SwiftOAuthCore has 28. These are not vanity tags — the packages have real downstream consumers within the portfolio, so version discipline has a practical consequence: a consumer can pin and be confident.

**Dependency honesty.** The MCPClient MASTER_PLAN includes an explicit correction: the project originally claimed zero dependencies, has since taken on AsyncHTTPClient, WebSocketKit, swift-crypto, and SwiftOAuth, and the plan records the moment the claim became false and why. This is rare — most documentation either hides drift or ignores it — and it is consistent with a project where the quality gate includes checking that documentation reflects reality.

**Determinism as a design constraint.** Deterministic, seeded RNG appears in IconquerCore (for TypeScript parity testing), IconquerAI (for reproducible agent play), and SwiftExcelFunctions (delegating math to BusinessMath so two implementations cannot disagree). The shared dependency `SwiftDeterminism` makes this explicit as infrastructure. BusinessMathMCP describes deterministic, auditable answers as its core differentiator over an LLM estimating a discount rate.

## Key Projects

**development-guidelines** (167 commits, 17 releases) is the rulebook that governs everything else. It defines Design-First TDD, the zero-warning quality gate, and the scaffolding — `setup.swift`, skills, hooks — that installs those rules on a project's first day. It is versioned and vendored rather than cloned so that each consuming project owns exactly one copy and updates are replacements. The 17 releases represent real discipline: every rule change that would break a consumer is a version bump. This project is foundational to interpreting the rest of the portfolio; 21 downstream projects carry its artifacts.

**The Iconquer Ecosystem** (8 packages, ~410 commits, 32 collective releases) is the portfolio's largest single effort. IconquerCore is the headless rules engine — pure value semantics, seeded RNG, no UI. IconquerMatch is the orchestration layer that binds players to seats, enforces move deadlines, and records every move. IconquerAI adds MLX-backed learned agents with self-play training and Wilson-interval win-rate measurement. IconquerCLILib wires these into a full terminal client with multiple AI backends, animated dice rolls, and batch simulation modes. IconquerServer is a SwiftNIO WebSocket backend that owns canonical game state and validates every client move before applying it, with actor-isolated concurrency throughout. IconquerClient, IconquerUI, and IconquerGameKit complete the stack: a typed WebSocket client library, a cross-platform SwiftUI presentation layer, and a unified observable view model. Taken together, the ecosystem covers rules engine, AI, multiplayer networking, terminal client, and cross-platform UI for a single game — each layer a separable, versioned package.

**MCPClient and SwiftMCPServer** (110 + 168 commits, 9 + 38 releases) represent the developer's investment in the Model Context Protocol as an integration surface. SwiftMCPServer handles protocol framing, HTTP transport, and OAuth so that a server built on it supplies only tools, resources, and prompts. MCPClient enables any Swift application to connect to MCP servers over HTTP/SSE, stdio, or WebSocket transports, with Swift 6 strict concurrency and actor-based isolation throughout. These two packages are the infrastructure on which BusinessMathMCP, SearchOperatorCore, and IconquerMCP are built — a bet that MCP becomes the standard channel between AI agents and running software, made early and made in both directions simultaneously.

**CTokenizer** (177 commits, 1 release) is a Metal compute pipeline for streaming Mixture-of-Experts language models through ~6GB resident memory from NVMe SSD on Apple Silicon, supporting architectures up to 200GB+ via runtime-configurable `ModelConfig`. It is the portfolio's only project with a formal design-first workflow on record. 226 tests cover all GPU paths using tiny synthetic model fixtures — no 200GB download required to run the suite. The OpenAI-compatible HTTP server includes SSE streaming, bearer-key authentication, sequence budgets, and cancellation on disconnect.

**SwiftExcelFunctions** (269 commits, 21 releases) implements Excel's function library in Swift with Excel's semantics — not similar semantics, Excel's: the same argument order, the same coercion behavior, the same error propagation, including the legacy and dotted name pairs that exist only for compatibility. The motivating application is a workbook-correctness CLI that reads a financial model, recomputes it, and reports disagreements. The mathematics is entirely delegated to BusinessMath to prevent two implementations of NPV from producing plausible but divergent numbers.

**narbis** (336 commits, 1 release) — the portfolio's most committed project by volume — is a cross-platform Swift library for real-time biofeedback using a patented HRV coherence algorithm. It runs fully on-device, processes BLE heart rate monitor data, and targets iOS, watchOS, visionOS, and Android via the Swift 6.3 SDK. OTA algorithm tuning via configuration means no App Store review cycle for threshold changes. With 336 commits and a single release, this project is still in heavy development — the commit volume reflects sustained, careful work rather than rapid shipping.

**SwiftCLIKit** (164 commits, 23 releases) is a pure Swift terminal UI library with two abstraction layers — a low-level terminal foundation and a high-level cell-based UI framework — plus an embedded SSH server module built on swift-nio-ssh, all with zero C dependencies beyond system libc. It is the terminal rendering layer for IconquerCLILib and available as a standalone library. Twenty-three releases against 164 commits indicates a library that has been actively maintained and broken out incrementally as its API stabilizes.

**ApplesoftBASICLib** (45 commits, 2 releases) and its companion app **ApplesoftBASICAppCore** exist because a program written in 1979 should behave the way it did — including the surprising parts. The library implements the full Applesoft BASIC interpreter including lo-res and hi-res Apple II graphics, the period-accurate line editor, and the original error messages. ApplesoftBASICAppCore presents it on iPad, Mac, and Vision Pro with PrintChar21/PRNumber3 fonts and green-on-black terminal rendering. The project is notable in this portfolio for what it is not doing: there is no modernization, no convenience wrapper, no "inspired by" approximation. Fidelity is the specification.
